# SauceDemo: test package

## Краткий тест-план

- **Цель:** проверить критический путь покупки и основные отрицательные ветки UI.
- **Объект:** публичный учебный сайт [SauceDemo](https://www.saucedemo.com/).
- **Объём:** вход, каталог, сортировка/добавление, корзина, checkout information, overview и подтверждение заказа.
- **Вне объёма:** реальные платежи, backend/API и база магазина (не предоставлены), нагрузочное и полное кросс-браузерное тестирование.
- **Данные:** `standard_user / secret_sauce`; синтетические имя и индекс. Заказ учебный, оплата не выполняется.
- **Подход:** smoke, позитивные/негативные сценарии, exploratory session, эквивалентные классы, границы и decision table для обязательных полей.
- **Риски:** учебный сервис может меняться или быть недоступен; специальный аккаунт `problem_user` тестируется отдельно от baseline.
- **Критерии завершения:** критические сценарии проходят; наблюдения воспроизводимы; ограничения окружения отделены от дефектов продукта.

## Чек-лист

> Чек-лист описывает запланированное покрытие, а не статус выполнения. Фактически выполненные ручные проверки и реализованные автотесты отмечены в таблице тест-кейсов и результатах ниже.

### Вход
- [ ] Валидные данные открывают каталог.
- [ ] Неверные данные показывают ошибку и не открывают каталог.
- [ ] Заблокированная учётка получает ожидаемое сообщение.
- [ ] Пустые поля валидируются.
- [ ] Logout завершает сессию; inventory требует вход.

### Каталог
- [ ] У товара есть название, цена, изображение и действие.
- [ ] Сортировка имени и цены соответствует направлению.
- [ ] Add to cart обновляет badge и состояние действия.
- [ ] Несколько выбранных товаров отражаются в корзине.
- [ ] Меню и возврат в каталог работают.

### Корзина
- [ ] Выбранные товары и цены показаны корректно.
- [ ] Remove удаляет строку и обновляет badge.
- [ ] Continue Shopping сохраняет оставшиеся позиции.
- [ ] Checkout из пустой корзины невозможен.

### Checkout
- [ ] Checkout открывает форму покупателя.
- [ ] First Name, Last Name, Postal Code валидируются отдельно как обязательные.
- [ ] Cancel возвращает в корзину, сохраняя выбранные товары.
- [ ] Overview показывает корректные позиции, subtotal, tax и total.
- [ ] Finish отображает подтверждение; Back Home возвращает в каталог.
- [ ] Повторный переход после завершения не создаёт ложное подтверждение.

## Тест-дизайн

### Эквивалентные классы и границы

| Поле | Классы/границы | Примеры | Ожидание |
|---|---|---|---|
| Login credentials | Валидная пара, неверный username, неверный password, оба неверны, пустой username/password | `standard_user/secret_sauce`, `invalid_user/secret_sauce`, `standard_user/wrong_password`, пустое поле | Только валидная пара входит; остальные видят ошибку |
| Checkout required fields | Все заданы; отдельно пропущено каждое поле | пустой First Name, Last Name или Postal Code | Продолжить только если заданы все три |
| Postal Code | Пусто, короткая строка, обычное значение, нестандартные символы | ``, `1`, `12345`, `A-1` | Проверить фактические ограничения, не предполагать формат |
| Cart size | 0, 1, N позиций | пусто, Backpack, Backpack + Bike Light | Для 1/N суммы и товары согласованы; пустой checkout запрещён |

## Результаты exploratory testing

- **Дата:** 2026-10-18. **Браузер:** Codex in-app browser. **Чартер:** login → catalog → cart → обязательное поле checkout; отдельный осмотр `problem_user`.
- `standard_user` перенаправлен в `/inventory.html`, каталог содержит 6 товаров и варианты сортировки — пройдено.
- Backpack добавлен; корзина показала одну позицию `$29.99` — пройдено.
- При пустом First Name и заполненных остальных полях UI остался на форме и показал `First Name is required` — ожидаемая валидация.
- Overview: item total `$29.99`, tax `$2.40`, total `$32.39`; Finish показал “Thank you for your order!” и очистил badge — пройдено (только учебный заказ).
- `problem_user`: на Backpack, Bike Light, Bolt T-Shirt и Fleece Jacket видна одна и та же фотография собаки вместо фото товара. Сценарии checkout под этой учёткой здесь не утверждаются.

### Баг-репорт SD-BUG-01: одинаковое нерелевантное изображение у товаров для `problem_user`

- **Статус:** воспроизведено в публичном учебном окружении; в Sauce Labs не отправлялось.
- **Окружение:** SauceDemo, 2026-10-18, пользователь `problem_user`.
- **Severity:** S3, визуальный дефект малой серьёзности; текст/цена/покупка остаются доступны. **Priority:** P2 для этого учебного сценария.
- **Шаги:** открыть сайт → войти как `problem_user` с паролем, показанным на login → сравнить изображения и названия карточек каталога.
- **Ожидание:** каждая карточка показывает изображение своего товара.
- **Факт:** видимые карточки показывают одну фотографию собаки, хотя имена, описания и цены разные.
- **Доказательство:** визуально зафиксировано browser screenshot во время исследования (Backpack, Bike Light, Bolt T-Shirt, Fleece Jacket); файл снимка не экспортирован. Шаги воспроизводимы.
- **Влияние/границы:** мешает визуальной идентификации товаров; относится только к специально проблемной demo-учётке. Это не утверждение о `standard_user` или production.

## SQL и границы данных

Учебный магазин не предоставляет доступ к своей БД. SQL в `sql/order_consistency_checks.sql` — отдельная иллюстративная схема, запросы не сверяются с заказом SauceDemo. Нельзя утверждать, что UI-заказ записался в эту учебную базу.
